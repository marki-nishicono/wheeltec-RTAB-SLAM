# 手动行驶、30 fps 预览与三维视图更新

按最新要求，删除障碍距离拦截逻辑，前后最近激光回波仅用于显示。不使用 10 cm 或 15 cm 停车阈值。W/S、前进后退及转向按钮统一使用 0.10 m/s；A/D 配合 W/S 转向。车端仍有 0.12 m/s 输入限幅、350 ms 指令看门狗、底盘/雷达失联停车，浏览器仍保留松键、空格、失焦停车。

## 相机与数据频率

Astra 配置的 `color_mode: 7` 是枚举编号，含义为 640×480@30Hz，并非 7 fps。该模式本车测得 RGB 约 21.9 fps，深度 29.7 fps。切换编号 10（320×240@30Hz）后，两路测得约 29.6–29.7 fps。`launch/camera.launch` 保存了这个档位。

驱动面对尺寸与原厂标定文件不符时会切换为通用内参。为避免无声改变几何，前端读取 `config/astra_rgb_640.yaml`（原厂标定只读副本），按实际宽高同比例缩放 K，保留 D，联合矫正 RGB 和配准深度。原车标定文件未覆盖。

相机原始 RGB → 单次 JPEG 编码 → SSH → 本机 MJPEG 预览。编码结果由多个浏览器共享，队列仅保留最新帧，避免落后视频堆积。实测完整本机代理链路 150 帧 / 约 5 秒，29.69 fps、约 324 KiB/s。该测试记录位于 `results/control_recovery/live_stream_check.json`。

RGB-D 建图前端仍为约 5 Hz，RTAB 更新仍为 1 Hz；30 fps 指相机采集及预览，并非 30 Hz 后端优化。预览流不执行本机点云解算。切换分辨率后的实验使用新数据库 `~/wheeltec_slam_runtime/maps/lab_30fps.db`，之前的 `lab_calibrated.db` 及导出快照保留。

## 三维显示

修正本机斜视投影的 Z 轴符号：世界坐标正 Z 对应屏幕向上。另修正原始轮式里程计 position.z 被厂家用于存储 yaw 的情况，绘制轨迹时将高度设为 0，不再把航向角当高度。

新增「车载相机视角」，使用车端 TF 给出的 `map_from_camera` 与已缩放的相机内参，在浏览器完成透视显示。位姿来自真实光学坐标系，视角随车移动；背面点和过期相机位姿不显示。滚轮缩放、适配视图复位倍率；此模式不支持拖动改变相机安装方向。

该视图显示已建成点云，不是用 RGB 伪造深度，也不是稠密表面重建。Astra-S 的有效深度窗口仍为 0.5–2 m；如果当前场景的深度有效率为零，相机方向的点云可能很稀疏，即使 RGB 视频正常。

## 车端负载

约每秒在车端读取 `/proc/stat`、`/proc/meminfo` 及 Jetson `/sys/devices/gpu.0/load`：

- CPU：全部 CPU 核的时间增量平均利用率，0–100%，不是多核累加百分比。
- 内存：`MemTotal - MemAvailable`，显示已用/总量和百分比。
- GPU：Jetson 驱动的千分比负载换算为百分比；无法读取时显示「—」，不伪造为 0。Jetson GPU 与 CPU 共享系统内存。

现场采样 CPU 约 16–19%、内存约 45–47%、GPU 0%。这些是短时观测，不是长时间性能保证；当前 SLAM 与编码主要运行在 CPU 上，GPU 0% 合理。

## 验证

14 个 Python 检查覆盖运动学、失联状态、近距和无回波不再拦截、指令看门狗；Node 检查 WASD/空格/松键、Z 轴方向、光学相机投影与背面裁剪。实际浏览器检查没有 JavaScript 错误，已核实实时 MJPEG、负载读数、三维地图和相机视角。新版已观测到指令与轮速均约 0.10 m/s；没有为测试而驶向障碍。
