# 实验台使用流程

入口：http://127.0.0.1:8080/ 。不要直接使用 file:// 页面作为实验台。文件入口已加入跳转；若浏览器阻止本地文件脚本，请直接打开 HTTP 地址。

## 每次车辆重新上电后

1. 车辆接入原网络，在本机项目目录运行 `bash scripts/start_lab.sh`。需要时在终端输入 SSH 密码。脚本建立独立控制/显示隧道，启动车端四项服务及本机页面和控制中继。
2. 页面顶部检查底盘、雷达、RGB-D 相机是否有新数据，右侧查看电压。连接失败会明确提示，地图列表每 5 秒重试，也可手动刷新。
3. 首次采集点击“新建地图并开始”，保持静止等待初始化完成。已有地图则选择非空地图，点击“从已保存地图继续”，静止匹配、IMU 校准和复核完成后再驾驶。重启后不沿用旧里程计原点。零节点地图没有可匹配内容，不能续建。
4. 出现“建图就绪”后，勾选行驶使能。W/S 前后，配合 A/D 转向，空格刹车并取消使能。相机前方尽量保持 0.5–2 m 有物体。
5. 相机预览和特征展示按需打开；不打开预览也会正常采集与建图。若相机无新图像，预览接口返回明确错误，页面显示重试状态。
6. 结束时空格停车、填写地图名称、点击“保存当前地图”。保存完成后可继续采集。删除所选地图会删除保存副本，当前工作副本独立保留。

## 电池提醒

读取底盘驱动 `/PowerVoltage`（Float32，伏特）。车端使用单调时钟；连续新鲜读数严格低于 9.9 V、持续严格超过 20 秒时，页面显示醒目的“请及时充电”提醒。恢复至 9.9 V 或以上重置计时；超过 2 秒无读数标为未知并重置连续计时。仅提醒，不新增低电压自动停车策略。页面刷新不会重置车端计时，车端服务重启会重新计时。

## 本次验证

实车电压约 11.10 V；底盘、雷达、RGB-D 数据恢复。浏览器地图列表正常加载，相机实际解码 117 帧；相机采集约 29.6 fps，H.264 预览约 9 fps、98.8 kbps；关闭后预览回到 0 fps、0 kbps。通过浏览器新建“实验室 · 电池监测与建图”，静止校准完成，状态为建图就绪并已有 2 个节点，未发送运动测试指令。33 项 Python 测试及键盘、投影、视频开关测试通过。低电压 20 秒边界通过模拟时钟测试，未人为放电触发实车告警。
